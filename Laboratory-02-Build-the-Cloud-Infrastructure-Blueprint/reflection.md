# Mission Reflection

## 1. Most Important Cloud Infrastructure Component

The network component is arguably the most critical element because it serves as the foundational backbone connecting all other services. Without robust, secure virtual private networks, subnets, and routing, compute instances cannot communicate, storage repositories remain inaccessible, and end users cannot interact with deployed applications. A well-designed network architecture ensures security, low latency, and high availability across the entire cloud environment.

## 2. Linux and Cloud Computing

Linux is the dominant operating system powering modern cloud computing due to its open-source nature, lightweight footprint, and stability. Most cloud-native technologies—including container runtimes like Docker and orchestration platforms like Kubernetes—are designed natively on Linux. Mastering Linux command-line operations, shell scripting, and permission management is essential for efficiently automating server deployments, managing virtual machines, and troubleshooting cloud-hosted workloads.

## 3. Importance of Technical Documentation

Technical documentation is crucial for maintaining clarity, reproducibility, and scalability in system architecture. High-quality documentation ensures that complex configurations, security policies, and deployment steps are transparent to teammates and future maintainers, drastically reducing onboarding time and operational downtime during incidents. It also bridges the gap between technical implementation and business requirements by providing an accurate source of truth for audits and architectural reviews.

## 4. New Skills Learned

Through this mission, I developed a deeper understanding of mapping foundational cloud infrastructure components across major providers like AWS, Azure, and GCP. I improved my ability to construct architectural flowcharts to visualize traffic flow between users, networks, compute nodes, and storage layers. Additionally, I strengthened my technical writing skills by structuring clear, concise Markdown documentation tailored for technical and peer reviews.

## 5. Improvement of My GitHub Portfolio

To improve my GitHub portfolio, I will structure my repositories with clear `README.md` files that include system architecture diagrams, setup guides, and project overviews to showcase production-readiness. I will also consistently commit clean, modular code paired with automated workflows (such as GitHub Actions for CI/CD) and document my problem-solving process to highlight both my technical execution and engineering discipline.
